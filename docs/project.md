# Project: ALVR (Air Light VR) 18.2.3

> Audited from the source tree on 2026-10-24. This copy has no `.git` directory, so history-derived facts (release cadence, authorship, prior decisions) are not available. The version 18.2.3 is declared by every workspace crate and by the Android client (`versionName "18.2.3"`, `versionCode 84`).

> **Dependency upgrade and UI migration (2026-10-24).** Every direct Rust dependency was raised to its latest stable release, with one exception: `bincode` 3.0.0 is an empty `compile_error!` tombstone, so the tree uses `bincode` 2.0.1. All host crates (`alvr_launcher`, `alvr_server`, `alvr_audio`, `alvr_sockets`, ...) were ported and pass `cargo check` on Windows. `alvr_client` (Android) is ported to `jni` 0.22, `oboe` 0.6 and `android_logger` 0.15 and builds with Gradle (`gradlew assembleOculusGoStableDebug` succeeded and produced a debug APK; it was not installed on a headset). `cargo check --target aarch64-linux-android` outside Gradle needs the NDK toolchain in `CC_aarch64_linux_android`, `AR_aarch64_linux_android`, `CXX_aarch64_linux_android` and `LIBCLANG_PATH`); the Gradle build and a headset run were not done. The Linux-only crates were not checked.

> **Fork direction.** This tree is the base for a fork of ALVR 18.2.3 aimed only at the Oculus Go. No Go-specific patches exist yet; the build toolchain has been modernized and CI workflows were removed (see Toolchain versions below). The Go-specific entry points that already exist are the `OculusGo` Android flavor, `cargo xtask build-client --oculus-go`, and the client's `VRAPI_DEVICE_TYPE_OCULUSGO` detection.

ALVR streams VR games from a Windows or Linux PC to a standalone Android headset over Wi-Fi. The PC runs an OpenVR driver loaded by SteamVR; the headset runs an Android app that decodes the stream and displays it through Oculus VrApi.

## Stack

- **Rust 2021** (declared MSRV 1.58; the updated dependency graph requires 1.95, verified on 1.99.1). One Cargo workspace with 14 members under `alvr/`.
- **Async and networking**: Tokio, `tokio-util` codecs, `serde`/`bincode` 2 (`legacy` config, wire-compatible with 1.x; bincode 3.0.0 is an empty `compile_error!` tombstone), `rcgen`. There is no HTTP server or client any more.
- **C++17**, compiled into the Rust crates with the `cc` crate. FFI bindings are generated by `bindgen`, which needs libclang at build time. The server vendors OpenVR headers and the client vendors Oculus VrApi headers.
- **Android**: Java plus Gradle 9.6.0 (wrapper) / Android Gradle Plugin 9.4.1, JDK 21, NDK 27.1.12297006, `compileSdk` 36 and `targetSdk` 31, `minSdk` 24 for Quest and 21 for Go, `arm64-v8a` only. The Rust library is built by `org.mozilla.rust-android-gradle` 0.10.0.
- **Desktop UI**: [egui](https://github.com/emilk/egui) through `eframe` 0.37 for every desktop window: launcher, dashboard and settings. This replaces `druid` and `gtk` (launcher), `alcro` (embedded Chromium dashboard window), `webbrowser` (opening links), the hyper/WebSocket web server and the static web dashboard (Bootstrap 4, jQuery, RequireJS, lodash, D3, uPlot, Lobibox). The launcher and the in-process dashboard window (Monitor, Settings, Installation, About) are egui; see architecture.md for what was not ported.
- **Audio**: `cpal`/`rodio`, using WASAPI on Windows and ALSA or JACK on Linux.
- **Video**: NVENC, AMD AMF VCE, and FFmpeg pipelines (NVENC, VAAPI, software) on Linux; Android MediaCodec on the headset.

## Toolchain versions (upgraded 2026-10-24)

On 2026-10-24 the Rust dependency graph and the Android build were upgraded so the tree compiles on Rust 1.99.1, JDK 21 and AGP 9.4.1. CI workflows were removed; all builds are local. `targetSdk` stays at the upstream value of 31 to avoid changing Android 12+ runtime behavior. The release lint check for the Play Store target-SDK rule (`ExpiredTargetSdkVersion`) is disabled because ALVR is sideloaded, not distributed through Play.

## Repo Structure

| Path | Purpose |
|---|---|
| `alvr/common` | Version constants, semver compatibility check, logging front-end, shared panic hook, hashed OpenVR device paths. |
| `alvr/session` | `SessionDesc`, `OpenvrConfig`, the full settings tree, schema generation, JSON persistence and migration. |
| `alvr/sockets` | Control socket (TCP, length-delimited bincode), stream sockets (UDP, throttled UDP, TCP), packet definitions, stream IDs. |
| `alvr/audio` | Audio device enumeration and selection, game audio capture, microphone playback, Windows device-ID lookup (desktop only: `cpal`/`rodio` are not built for Android, whose CPAL backend needs AAudio, API 26+, while the Go runs Android 7). The sample buffering used by the Android client is always built. |
| `alvr/filesystem` | Installation layout for Windows, Linux FHS, portable `--root` builds, logs, config and driver paths. |
| `alvr/commands` | OS integration: OpenVR driver registration, SteamVR detection/restart, firewall rules, launcher helper. |
| `alvr/launcher` | `ALVR Launcher.exe` / `alvr_launcher`: SteamVR preflight, driver registration, SteamVR launch. Window is egui (`eframe`). |
| `alvr/server` | SteamVR driver: Rust lifecycle/networking, egui dashboard window and readiness beacon, plus C++ OpenVR devices, encoders, compositor and rendering. |
| `alvr/client` | Android client: Rust networking/input plus C++ VrApi rendering, NAL/FEC handling, Java activity and decoder threads. `OculusGo` and `OculusQuest` product flavors; this fork targets `OculusGo`. |
| `alvr/settings-schema`, `alvr/settings-schema-derive` | Generic JSON-schema model and derive macro used by the settings tree. |
| `alvr/vulkan-layer` | Linux Vulkan layer that exposes a capture display to SteamVR and shares swapchain images with the driver. |
| `alvr/vrcompositor-wrapper` | Linux wrapper that loads the ALVR Vulkan layer, disables Steam Fossilize, then execs `vrcompositor.real`. |
| `alvr/xtask` | Build, dependency, version-bump and packaging automation (`cargo xtask`). |
| `packaging` | Linux build script, DEB/RPM metadata, Nix shells, firewall scripts, SELinux policy, desktop entry. |
| `resources` | Project logo. |
| `.github` | Issue template and funding configuration. CI workflows, Dependabot and stale configuration were removed. |

## Build & Test

### Prerequisites

- Rust stable (verified 1.99.1; the updated dependency graph requires 1.95 or newer) with `rustfmt` and `clippy`.
- A C++17 toolchain and libclang (for `bindgen`). On Windows, `pip install --user libclang==18.1.1`, then set `LIBCLANG_PATH` to the directory printed by `python -c "import clang, os; print(os.path.join(os.path.dirname(clang.__file__), 'native'))"`. This avoids a system-wide LLVM install.
- Windows: Visual Studio 2022 Build Tools (2019 also compiles the C++ code). WiX 3.14 is optional and only used to build the MSI/bundle.
- Android: JDK 21, Android SDK 36, NDK 27.1.12297006, and `rustup target add aarch64-linux-android`.
- Linux packages needed for a local build:

```bash
sudo apt install build-essential pkg-config nasm libva-dev libdrm-dev libvulkan-dev \
  libx264-dev libx265-dev cmake libasound2-dev libjack-jackd2-dev \
  libunwind-dev libffmpeg-nvenc-dev nvidia-cuda-toolkit
cp packaging/deb/cuda.pc /usr/share/pkgconfig
cargo xtask build-ffmpeg-linux
cd deps/linux/FFmpeg-n4.4 && sudo make install && cd ../../..
```

### Build

```bash
# Windows server, launcher and xtask
cargo build -p alvr_xtask -p alvr_server -p alvr_launcher --verbose

# Linux (after FFmpeg is installed)
cargo build -p alvr_xtask -p alvr_launcher -p alvr_server -p alvr_vulkan_layer \
  -p vrcompositor-wrapper --verbose

# Full server/client build into ./build through xtask
cargo xtask build-server --release
cargo xtask build-android-deps
cargo xtask build-client --oculus-go
```

`cargo xtask publish-client` still builds both headsets; a Go-only fork release should call `build-client --oculus-go` or trim `publish-client` to the Go flavor.

### Test and lint

```bash
cargo test -p alvr_session --verbose
cargo fmt --all -- --check
cargo xtask clippy
```

`alvr_session` is the only crate with automated tests (session/settings migration). There is no end-to-end or network integration test in the tree.

### Package and release

```bash
cargo xtask build-windows-deps
cargo xtask build-android-deps
cargo xtask build-ffmpeg-linux
cargo xtask publish-server [--gpl] [--nightly] [--reproducible]
cargo xtask publish-client [--nightly]
cargo xtask bump-versions [--version X] [--nightly]
cargo xtask clean
cargo xtask kill-oculus
```

Artifacts land under `build/`: `alvr_server_windows.zip`, `ALVR_Installer_v<version>.exe` when WiX is present, `alvr_server_linux.tar.gz`, `alvr_server_linux_portable.tar.gz`, and `alvr_client_oculus_{quest,go}/*.apk`. Linux DEB/RPM and other package targets are driven by `packaging/alvr_build_linux.sh`.

### Run locally

```text
ALVR Launcher.exe        # Windows installed/portable layout
alvr_launcher            # Linux
```

The launcher registers the driver if needed, starts SteamVR, and then waits until the driver's readiness beacon accepts a TCP connection on `127.0.0.1:8082`; the dashboard then appears as a native window.

### Known tooling gaps

- `cargo xtask clippy` covers only `alvr_xtask`, `alvr_common` and `alvr_launcher`; other crates are excluded because of existing clippy warnings.
- AGP 9.4.1 uses the legacy Android DSL (`android.newDsl=false`) because `rust-android-gradle` 0.10.0 does not support AGP 9's new DSL. AGP 10 removes that opt-out, so the Rust plugin must gain new-DSL support before then.
- No CI: workflows were removed from this fork, so nothing runs automatically on push. Builds, tests and packaging are local; `cargo xtask publish-*` produces artifacts under `build/` but does not upload them.
- The Linux-only crates (`alvr_vulkan-layer`, `vrcompositor-wrapper`) were not built on this Windows machine.

## External Dependencies

| Dependency | Role | Notes |
|---|---|---|
| SteamVR / OpenVR runtime | Loads the ALVR driver and supplies the compositor and tracking space | Required on the PC. The launcher checks that SteamVR has been started once. |
| Oculus VrApi and Oculus platform loader | VR runtime on the headset | Vendored headers and `libvrapi.so` / `libovrplatformloader.so` are in the client tree. |
| Android MediaCodec | Hardware H.264/HEVC decode | Decoder threads in Java feed the native renderer. |
| FFmpeg 4.4 (Linux) or FFmpeg 5.0 DLLs (Windows, `--gpl`) | VAAPI/NVENC/software encode pipelines | Built or downloaded by `cargo xtask`. |
| NVENC, AMF VCE, VAAPI | Hardware video encode | Selected by platform and codec settings. |
| NVIDIA / AMD / Mesa drivers | Vulkan and encode support | The server enumerates GPUs through `wgpu` and disables Linux async reprojection on NVIDIA. |
| libclang | Bindgen | Build-time only. bindgen 0.73 needs libclang 9+; 18.1.1 is used locally. |
| WiX 3.14 | Windows MSI and bundle | Optional; skipped when `WIX` is unset. |
| `cargo-about` | Third-party license bundle | Installed by `publish-server`. |
| OS firewall | Inbound access for the driver | `netsh` on Windows, `ufw`/`firewalld` scripts on Linux. |

## Versioning

- Workspace crates are kept at one version: `18.2.3`.
- `cargo xtask bump-versions` writes the new version into every crate manifest, the Android `versionName` (and increments `versionCode` for stable releases), the RPM spec and the DEB control file.
- Nightly builds use `<version>+nightly.YYYYMMDD`.
- Client and server are compatible when their major versions match. For prerelease versions the comparison is exact, including the prerelease tag; build metadata is ignored.
- On a version change, the driver clears the stored client list at startup (`alvr/server/src/lib.rs`).
